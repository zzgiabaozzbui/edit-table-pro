edit-table-pro

A high-performance editable table for React. Built for datasets with thousands of rows — virtual scroll, per-column validation, side effects, undo/redo, and fill handle, with zero runtime dependencies.

<EditableTable
  columns={columns}
  initialData={data}
  getRowId={(row) => row.id}
  height={600}
/>

Install

npm install edit-table-pro

Peer dependencies: React ≥ 18, React DOM ≥ 18

Then import the stylesheet once in your app entry point:

import 'edit-table-pro/style.css'

Quick Start

import { EditableTable } from 'edit-table-pro'
import type { ColDef } from 'edit-table-pro'
import 'edit-table-pro/style.css'

type Product = {
  id: string
  name: string
  price: string
  stock: string
}

const columns: ColDef<Product>[] = [
  { key: 'name',  type: 'text',   header: 'Name',  width: 200 },
  { key: 'price', type: 'number', header: 'Price', width: 100,
    validate: (v) => Number(v) >= 0 ? { ok: true } : { ok: false, error: 'Must be ≥ 0' } },
  { key: 'stock', type: 'number', header: 'Stock', width: 100 },
]

const data: Product[] = [
  { id: '1', name: 'Widget A', price: '9.99',  stock: '100' },
  { id: '2', name: 'Widget B', price: '14.99', stock: '50'  },
]

export default function App() {
  return (
    <EditableTable
      columns={columns}
      initialData={data}
      getRowId={(row) => row.id}
      height={400}
    />
  )
}
Note: All row values must be string. Numbers, dates, and booleans are stored as strings and formatted/validated per column.

Getting Started

Install

npm install edit-table-pro

Peer dependencies: React ≥ 18, React DOM ≥ 18

Import the stylesheet

Import once in your app entry point (main.tsx, App.tsx, or a global CSS file):

import 'edit-table-pro/style.css'
Without this import the table renders with no visual styles.

Step 1 — Define your row type

All cell values must be string. Numbers, dates, and booleans are stored as strings.

type Product = {
  id: string
  name: string
  price: string
  stock: string
}

Step 2 — Define columns

import type { ColDef } from 'edit-table-pro'

const columns: ColDef<Product>[] = [

  { key: 'price', type: 'number', header: 'Price', width: 100 },

Every column must have key, type, and usually header and width.

TypeScript

The library ships full type definitions. No @types/ package needed.

Your row type must satisfy Record<string, string>. If your data source returns number | boolean, convert before passing to initialData.

ColDef Reference

Every column is described by a ColDef<T> object.

Required fields

key

Maps to a property on your row type. Must be a string key of T.

type

type: 'text' | 'number' | 'date' | 'select' | 'boolean'
Note: All values are stored as strings regardless of type. type is metadata your validate and format callbacks can use.

Display fields

FieldTypeDefaultDescription
headerstringkeyColumn header label
widthnumber150Initial column width (px); user can drag to resize
align'left'|'center'|'right''left'Text alignment inside the cell
ellipsisboolean—Clip overflow text with ellipsis instead of wrapping
hiddenboolean—Hide from table and CSV export

Editing — editable

editable?: boolean | ((row: T) => boolean)

Controls whether a cell is editable. Dynamic example:

{
  key: 'price', type: 'number',
  editable: (row) => row.status !== 'approved',
}

Validation — validate

validate?: (value: string, row: T) => ValidationResult

type ValidationResult =
  | { ok: true }
  | { ok: false; error: string }

Synchronous, called on every keystroke. The error string is shown as a tooltip.

Formatting — format

format?: (value: string) => string

Transforms a committed value before it is stored. Called after a successful validate pass, on blur/Enter.

{
  key: 'phone', type: 'text',
  format: (v) => v.replace(/\D/g, ''),
  validate: (v) =>
    v.replace(/\D/g, '').length >= 10
      ? { ok: true }
      : { ok: false, error: 'Need at least 10 digits' },
}

Side effects — sideEffect

sideEffect?: {
  trigger: 'change' | 'blur'
  debounceMs?: number
  handler: SideEffectFn<T>
}

Runs async logic after a cell changes. See Side Effects for details.

Custom render — render

render?: (value: string, row: T, index: number) => ReactNode

Replaces the default input. Column is excluded from CSV export; keyboard navigation skips it.

Full example

const columns: ColDef<Product>[] = [
  { key: 'code',   type: 'text',   header: 'Code',   width: 100, align: 'center',
    validate: (v) => /^\d+$/.test(v) ? { ok: true } : { ok: false, error: 'Digits only' } },
  { key: 'name',   type: 'text',   header: 'Name',   width: 220, ellipsis: true },
  { key: 'price',  type: 'number', header: 'Price',  width: 100, align: 'right',
    validate: (v) => Number(v) >= 0 ? { ok: true } : { ok: false, error: 'Must be ≥ 0' } },
  { key: 'status', type: 'text',   header: 'Status', width: 100, editable: false },
  { key: 'id',     type: 'text',   header: '',       width: 60,
    render: (_, row) => <button onClick={() => open(row.id)}>Open</button> },
]

Validation

Synchronous per-cell validation. Errors are shown inline and the value is not committed until validation passes.

Basic validation

{
  key: 'price', type: 'number',
  validate: (value) =>
    Number(value) >= 0
      ? { ok: true }
      : { ok: false, error: 'Must be ≥ 0' },
}

When validation runs

Validation is called on every keystroke. If it fails:

  • The cell shows a red border and error tooltip
  • The value is not committed — row data is unchanged
  • User must fix the input, or press Escape to restore previous value

Cross-column validation

The second argument is the current row object:

{
  key: 'maxStock', type: 'number',
  validate: (value, row) => {
    const max = Number(value)
    const min = Number(row.minStock)
    if (Number.isNaN(max)) return { ok: false, error: 'Must be a number' }
    if (max < min)          return { ok: false, error: 'Must be ≥ min stock' }
    return { ok: true }
  },
}

Common patterns

Required field

validate: (v) => v.trim().length > 0 ? { ok: true } : { ok: false, error: 'Required' }

Numeric range

validate: (v) => {
  const n = Number(v)
  if (Number.isNaN(n)) return { ok: false, error: 'Must be a number' }
  if (n < 0)            return { ok: false, error: 'Must be ≥ 0' }
  if (n > 10000)         return { ok: false, error: 'Must be ≤ 10,000' }
  return { ok: true }
}

Date format

validate: (v) => /^\d{4}-\d{2}-\d{2}$/.test(v)
  ? { ok: true } : { ok: false, error: 'Use YYYY-MM-DD format' }

Email

validate: (v) => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(v)
  ? { ok: true } : { ok: false, error: 'Invalid email' }

Validation + format order

On blur/Enter:

  1. validate(rawValue, row) — if ok: false, stay in error state, do not commit
  2. format(rawValue) — transform the value
  3. Store formatted value into row data

Dirty rows only contain validated values

Cells still in error state are not in dirtyRowsRef — only committed, valid values are tracked.

Side Effects

Run async logic after a cell value changes — auto-save, dependent field updates, external lookups.

Defining a side effect

{
  key: 'price', type: 'number',
  sideEffect: {
    trigger: 'blur',
    handler: async (value, ctx) => {
      await savePrice(ctx.rowId, value)
    },
  },
}

Handler signature

type SideEffectContext<T> = {
  signal:   AbortSignal             // cancel in-flight requests
  patchRow: (patch: Partial<T>) => void  // update sibling fields
  rowId:    RowId                   // row's unique ID
}

trigger: 'blur' vs 'change'

TriggerWhen it firesUse for
'blur'Once, when the user leaves the cellAuto-save, server validation
'change'Every keystroke (use debounceMs)Live search, suggestions

Updating other fields with patchRow

{
  key: 'productCode', type: 'text',
  sideEffect: {
    trigger: 'blur',
    handler: async (code, ctx) => {
      const product = await api.getProduct(code, { signal: ctx.signal })
      if (product) ctx.patchRow({ name: product.name, price: String(product.price) })
    },
  },
}

Abort on rapid change

Every call gets a fresh AbortSignal. If the cell changes again before the handler resolves, the previous signal is aborted.

handler: async (value, ctx) => {
  const res = await fetch(`/api/check/${value}`, { signal: ctx.signal })
  const data = await res.json()
  ctx.patchRow({ status: data.status })
}

Debounce

sideEffect: {
  trigger: 'change',
  debounceMs: 300,   // fires 300ms after user stops typing
  handler: async (value, ctx) => { ... },
}

Commit queue

Side effects are serialized per row. If a side effect is still running when the user edits the same row again, the next commit is queued — preventing stale data from overwriting newer input.

Fill & Selection

Fill handle

Each cell shows a small drag handle in the bottom-right corner. Drag it to fill adjacent rows.

  1. Click a cell to focus it
  2. Hover over the bottom-right corner — cursor changes to a crosshair
  3. Drag down (or up) to fill rows

Series detection

Source valuesFill behavior
Single value (any type)Copy — same value in all filled cells
Two+ numbers with constant deltaNumeric series — increments by delta
Two+ ISO dates with constant deltaDate series — increments days by delta
Anything elseCopy
Single-source = always copy. A single "0900123456" is never auto-incremented — protecting phone numbers and codes with leading zeros.

Multi-cell selection

  • Click + drag horizontally in a row to select multiple cells
  • Shift + click another cell in the same row to select the range
  • Then drag the fill handle to fill all selected columns downward

Keyboard fill

ShortcutAction
Ctrl+DFill the active cell's value into the row below
Ctrl+RFill the active cell's value into the column to the right

Undo fill

All fill operations are a single undo step. Press Ctrl+Z to revert the entire fill at once.

Paste from Excel / Google Sheets

Copy cells from Excel or Sheets → click the top-left target cell → Ctrl+V.

  • Paste starts at the active cell and fills right and down
  • Extra columns are ignored
  • If pasted data has more rows than the table and createRow is provided, new rows are appended
  • Each pasted cell is validated before commit — invalid values are skipped
  • The paste is a single undo step

Editable-only fill

Fill only writes to cells where editable is true. Read-only cells in the range are silently skipped.

Appending rows programmatically

function ImportButton() {
  const { appendRows } = useTableContext()

    const rows = await fetchRowsFromApi()
    appendRows(rows)  // single re-render
  }
  return <button onClick={handleImport}>Import</button>
}

<EditableTable
  ...
  onSelectionChange={(ids) => setSelectedIds(ids)}

Adds a checkbox column. The header checkbox toggles all rows.

Row striping

rowClassName={(row, index) => index % 2 === 1 ? 'et-row-stripe' : ''}

Locking rows

editable: (row) => row.status !== 'approved'

Row identity

getRowId must return a stable, unique string per row. Used for dirty tracking, undo/redo, edit sessions, and selection reporting.

Warning: Using array index as row ID is fragile — if rows are reordered or inserted, IDs shift and tracking breaks.

Export & Submit

CSV Export

function Toolbar() {
  const { exportCsv } = useTableContext()
  return <button onClick={() => exportCsv('products.csv')}>Download CSV</button>
}

Hidden columns and render columns are excluded. UTF-8 BOM is prepended for Excel compatibility.

exportCsv outside a child component

function App() {
  const ctx = useEditableTable({ columns, initialData: data, getRowId })
  return (
    <>
      <button onClick={() => ctx.exportCsv('data.csv')}>Export</button>
      <EditableTable {...}ctx} height={500} />
    </>
  )
}

Collecting dirty rows

function SubmitButton() {
  const { dirtyRowsRef } = useTableContext()

  function handleSubmit() {
    const changed = []
    for (const [rowId, dirty] of dirtyRowsRef.current) {
      changed.push({ rowId, changes: dirty.current })
    }
    if (changed.length === 0) return
    saveToDB(changed)
  }
  return <button onClick={handleSubmit}>Save</button>
}

DirtyRow structure

type DirtyRow = {
  original: Record<ColKey, string>  // values at mount
  current:  Record<ColKey, string>  // latest committed values
}

Only committed (validated + formatted) values appear here. Cells in error state are not included.

Checking for unsaved changes

const hasChanges = ctx.dirtyRowsRef.current.size > 0

Clearing dirty state after save

ctx.dirtyRowsRef.current.clear()  // resets tracker without affecting displayed data

Performance Guide

How the table scales

Only rows within the visible viewport (plus overscan) are rendered. DOM node count is fixed at roughly visible height / row height + overscan — regardless of total row count.

The included demo uses 50,000 rows and scrolls at full frame rate.

Recommended row counts

Dataset sizeVerdict
< 1,000 rowsNo configuration needed
1,000–10,000 rowsUse size="small" if you want more rows visible
10,000–100,000 rowsWorks well; keep column count ≤ 20
> 100,000 rowsWorks, but JS array allocation is large — consider server pagination

Common pitfalls

validate on every keystroke

Keep validate synchronous and fast. Avoid regex with catastrophic backtracking or deep object cloning.

change-triggered side effects without debounce

sideEffect: { trigger: 'change', debounceMs: 300, handler: ... }

initialData inline (allocates new array each parent render)

// Bad
<EditableTable initialData={rawData.map(transform)} />

// Good
const data = useMemo(() => rawData.map(transform), [rawData])
<EditableTable initialData={data} />

render columns with closures

Use React.memo on rendered components when render body is heavy.

Limitations

All cell values must be strings

T must satisfy Record<string, string>. Convert your data on load and convert back before saving.

Single-row selection range only

Multi-cell selection and fill handle operate within a single row horizontally. No Excel-style multi-row rectangular selection.

No column freezing

Sticky (frozen) columns are not supported. All columns scroll together.

No row reordering

No drag-to-reorder. Rows display in the order of initialData / appendRows.

No built-in sort or filter

Apply sorting/filtering to initialData before passing it in. For server-side sort/filter, remount with key.

No async validation

validate is synchronous. For server-side checks, use sideEffect with trigger: 'blur' and update a status column.

No tree / grouped rows

Flat list only. No hierarchical rows or row groups.

No cell merging

colspan / rowspan are not supported.

No built-in pagination

Entire dataset lives in memory. For server-paginated data, use appendRows or remount with key.

Data reset requires remount

<EditableTable key={recordId} initialData={record.rows} ... />

When to use an alternative

Consider AG Grid, TanStack Table, or Handsontable if you need: multi-row rectangular selection, frozen columns, column visibility UI, server-side sort/filter/pagination UI, tree rows, cell merging, or formula evaluation.

edit-table-pro is best suited for data-entry forms as tables — a bounded dataset where users edit many rows quickly with validation, auto-save, undo/redo, and fill-down support.
